## 4. 리드 검토 (Claude, 2026-10-31)

agy 구현에서 아래를 고쳤다. main(오류 종류 LoadError, 영어 기본 + 한국어 문자열)을 먼저 병합했다.

### 고친 것
| 문제 | 조치 |
|---|---|
| `BookRepository.getBookPages`에 테스트 호환용 기본 구현(`emptyList()`) — "테스트 때문에 운영 코드 변경 금지" 위반 | 기본 구현 삭제, 다른 모듈 테스트 가짜에 메서드 추가 |
| `ReaderPreferences`에 쓰지 않는 개별 Flow 4개·`clearAll` | `readerSettings` + 저장 함수만 남김. 가짜만 검사하던 `ReaderPreferencesTest` 삭제 |
| ViewModel 오류 문구 하드코딩(`"책을 불러올 수 없습니다"`) | `ReaderUiState.Error(LoadError)` — 화면이 `loadErrorText`로 표시 |
| 쓰지 않는 "하위 호환" 별칭(`nextPage`, `jumpForward`, `currentPage` 등) | 삭제, 테스트는 실제 API 사용 |
| `runCatching`이 취소 예외까지 삼킴 | `CancellationException`은 다시 던지고 나머지만 로그 후 크기 없이 진행 |
| 시리즈 방향이 `VERTICAL`/`WEBTOON`이면 페이지 리더가 그 값을 그대로 씀 | 페이지 리더는 LTR/RTL만, 나머지는 저장된 기본값 (T6 전까지) |
| **화면 맞춤 깨짐** — 모든 모드를 `verticalScroll` 안에 두어 세로 제약이 무한대 → 화면 맞춤이 너비 맞춤처럼 됨 | 너비 맞춤·원본만 스크롤 컨테이너, 화면·높이 맞춤은 고정 상자 |
| **디코딩 크기**가 모든 모드에서 화면 크기 → 너비 맞춤이 흐려짐 | 모드별 크기(너비 맞춤 = 칸 너비 × 화면 높이 3배 상한 등) + `Precision.INEXACT`(디코딩에서 키우지 않음) |
| 작은 이미지 키우기(off)가 화면 맞춤에만 적용 | 너비·높이 맞춤에도 "줄이기만" ContentScale |
| 프리로드 요청 크기가 실제 표시와 달라 메모리 캐시를 못 씀 | 펼침 단위 `preloadSpreads`로 같은 요청을 만든다 |
| **오버레이의 "보기 설정" 버튼에 D-pad로 갈 수 없음** (리더가 모든 키를 먼저 가로챔) | 오버레이가 열린 상태에서 OK = 보기 설정. 버튼 대신 키 안내 문구 |
| 끝에 닿은 위/아래가 소비되지 않음 | 리더 방향키는 항상 소비 |
| **Back이 리더에 오지 않음** — targetSdk 36은 예측형 뒤로 가기가 기본이라 Back이 키 이벤트로 오지 않는다. 패널·오버레이를 열고 Back을 누르면 리더를 나가 버림 | `BackHandler`: 패널 → 오버레이 → 리더 종료 순서 |
| 설정 패널 아래 "닫기" 버튼이 1080p에서 잘림 | 버튼 삭제(Back으로 닫음), 키 안내 문구, 패널 세로 스크롤 |
| 두 쪽이 각자 칸 가운데에 놓여 가운데가 벌어짐 | 접히는 곳 쪽으로 정렬 |
| 문자열이 한국어로 `values/`에만 | 영어 `values/` + 한국어 `values-ko/`, 이름은 Komelia 영어 이름 |
| main에서 들어온 "%d pages" lint 경고(PluralsCandidate) 2건 | "Page %1$d/%2$d" |
