# T6 보고서: 세로 스크롤 리더 (웹툰, Komelia `CONTINUOUS`)

작업: Antigravity가 시작, 중간에 사용자 지시로 멈추고 Claude가 이어서 완성 — 2026-10-31
기준: Komelia (Apache-2.0) `ImageReaderSettings.kt`, `ReaderState.kt`, `ContinuousReaderState.kt`

## 1. 바꾼 것

### 설정 (core:model, core:datastore)
- `ReaderType`(`PAGED` 기본 / `CONTINUOUS`), `continuousPadding`(0f), `continuousPageSpacing`(0) — Komelia 이름·기본값. `PANELS`와 가로 연속 보기는 넣지 않음.
- `ReaderPreferences`에 세 값 저장.

### 리더 종류 우선순위 (Komelia `ReaderState`와 같음)
- 시리즈 방향 LTR/RTL → `PAGED`, `WEBTOON` → `CONTINUOUS`, `VERTICAL`/없음 → 저장된 값. 리더에서 바꾸면 지금 책에 바로 적용하고 기본값으로 저장, 보던 쪽에서 이어짐.

### 이어 읽기 (두 모드 공통)
- 진행이 없거나 완독이면 1쪽부터 (T5는 완독한 책을 마지막 쪽에서 열었음).

### 페이지 파일 캐시 (core:data `PageFileCache`)
- 세션 OkHttpClient(인증 포함)로 받아 앱 캐시 폴더에 저장, 200MB LRU. 같은 쪽 요청만 서로 기다리고 다른 쪽은 동시에 받는다.
- 성공이 아닌 응답은 `HttpStatusException(code)` — 401은 `LoadError.UNAUTHORIZED`로 바뀐다. 실패 응답도 닫는다. 취소되면 HTTP 호출을 끊는다.

### 타일 (feature:reader `continuous/`)
- `ContinuousTilePlanner` — 쪽 너비 = 화면 × (1 − 2 × 여백), 그렸을 때 화면 높이 이하인 세로 조각으로 나눈다 (웹툰 긴 쪽, 싼 TV의 4096px 텍스처 한도). 크기를 모르는 쪽은 화면 높이 자리표시.
- `TileDecoder` — 파일에서 타일 영역만 `BitmapRegionDecoder` + `inSampleSize` + RGB_565로 디코딩. 타일 48MB LRU, 영역 디코더 4개. 영역 디코딩이 안 되는 형식은 줄여 읽고 자른다. 리더를 떠나면 놓는다(`@ViewModelScoped`).
- `ContinuousPages` — `LazyColumn` 항목 = 타일, 보이는 타일만 디코딩.
- 크기를 모르는 쪽은 **보일 때만** 파일을 받아 크기를 알아내고 다시 계획한다.
- 타일을 다시 만들 때(여백·간격·키우기·화면 크기·쪽 크기 확인) 보던 자리(같은 쪽의 같은 높이)로 다시 스크롤한다.

### 화면·키
| 상태 | 좌/우 | 위/아래 | OK | Back |
|---|---|---|---|---|
| 세로 스크롤 읽기 | 이전/다음 쪽 처음 (맨 위가 쪽 중간이면 왼쪽은 그 쪽 처음) | 화면 높이만큼 스크롤 (Komelia) | 오버레이 | 진행 저장 후 나가기 |
| 오버레이 | 같음 | 10쪽 점프 | 보기 설정 | 오버레이 닫기 |
- 보기 설정 첫 줄 = 리더 종류. Paged는 T5 줄들, Continuous는 좌우 여백(0~45%, 5% 단위)·쪽 간격(0~64dp, 8 단위), 공통으로 작은 이미지 키우기.
- 진행: 보이는 쪽 중 가장 큰 번호를 2초 뒤 저장, 마지막 쪽의 마지막 타일이 보이면 완독. 다음 2쪽 파일을 미리 받는다.
- 쪽 목록을 못 받고 쪽 수도 0이면(서버 "Book analysis failed" 등) 검은 화면 대신 오류 문구.
- 문자열 영어 + `values-ko` (Reader type / 리더 종류, Paged / 페이지 넘김, Continuous / 세로 스크롤, Side padding / 좌우 여백, Page spacing / 쪽 간격).

## 2. Antigravity 작업에서 고친 것
| 문제 | 조치 |
|---|---|
| 크기 없는 쪽이 있으면 **책 전체를 미리 다운로드** (페이지 넘김 모드에서도), 백그라운드 스레드에서 상태를 바로 바꿈 | 보이는 쪽만, 메인 스레드에서 반영 |
| 캐시가 전역 잠금 하나 — 모든 다운로드가 한 줄로 | 쪽마다 잠금 |
| 실패 응답을 닫지 않음, 401을 일반 IOException으로 | `use`로 닫기, `HttpStatusException` |
| ViewModel 테스트를 다시 쓰며 **기존 테스트 5개 삭제** (WEBTOON 방향 대체, 로드 실패 오류 종류, 디바운스, 밀기, 크기 맞춤 저장) | 원래 테스트 복원 후 T6 테스트 추가 |
| 캐시 테스트가 연결 단계에서 실패하는 상태 (실행해 보지 않음) | 사용자 JSON 고쳐 통과 |
| 타일 계획 테스트의 기대값 오류 (1000×800 쪽을 너비 1920에 맞추면 1536px — 타일 2개가 맞음) | 테스트 수정 |
| 순수 계획 코드에 `android.graphics.Rect`, 출처가 아닌 코드에 Komelia 출처 주석 | 제거 |
| 화면 코드 없음 (중단 시점) | Claude 작성 |
