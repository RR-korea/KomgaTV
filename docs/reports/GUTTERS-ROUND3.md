### [유형 A] 어두운 배경(검은 바탕) 페이지의 흰색 채움 / 흰 띠 생성 (52쪽)

  - `터치 07권 0006.jpg`, `0013.jpg`, `0015.jpg`, `0016.jpg`, `0017.jpg`, `0018.jpg`, `0020.jpg`
  - `불새 03권 0128.png`, `0129.png`, `0228.png`
  - `TOKKO 02권 0003.jpg`
  - `3x3EYES 05권 0076.jpg`, `0166.jpg`, `0192.jpg`
  - `미생 02권 0005.png`
- **원인 분석**:
  - `padColor`가 여백을 채울 때 `page.evenest(sample, 0, width)`를 사용하는데, `evenest`의 정렬 기준 1순위가 `outliers`였음.
  - 검은 바탕 만화에서 스캔 가장자리(예: 최상단 y=0)에 묻은 얇은 흰색 스캔 여백은 단색이라 `outliers == 0`이 됨.
  - 이로 인해 바탕색(`bg`)이 검은색(20~30)임에도 불구하고 `outliers`가 0이라는 이유로 최상단의 흰 줄이 선택되어, 상하단 및 칸 간격 여백이 새하얗게 칠해지는 심각한 연출 왜곡 및 띠가 발생함.

### [유형 B] 2쪽 펼침면(Spread) 분할 오류 및 한 장 그림 파괴 / 높이 어긋남 (616쪽)

- **원인 분석**:
  - 가로가 넓은 펼침면(`width > height * 1.15`)에서 좌우로 나눌 때, `spreadSpine`이 가운데 접힌 곳을 지나는 가로 잉크를 감지하지 못하면(접힌 곳 빛번짐, 얇은 펜선 등) 더블 페이지 한 장 그림임에도 무리하게 분할을 시도함.
  - 더욱이 분할 후 좌우 반쪽 중 한쪽만 여백이 줄어들고 다른 쪽은 안 줄어들거나, 줄어든 양이 서로 다를 경우, 좌우 페이지 칸의 상하 정렬 위치가 완전히 어긋나거나 한쪽 쪽의 거대한 그림이 통째로 소실됨.

### [유형 C] 비스듬한 여백(Ribbon)의 컷 내부 침범으로 인한 그림 왜곡

## 5. 고친 내용 및 단위 테스트

### 1) 어두운 배경(검은 바탕) 페이지의 여백 채움 색상 안전장치 강화
- `Gutters.kt`의 `PageMaps.evenest`:
  - 바탕색 `bg`가 어두운 경우(`bg < 80`), 밝은 줄(`median > 140`)은 패딩 후보에서 제외.
  - 바탕색 `bg`가 밝은 경우(`bg > 180`), 어두운 줄(`median < 100`)은 패딩 후보에서 제외.
  - 스캔 테두리 잡티 줄이 전체 페이지 여백 색상을 오염시키는 것을 원천 차단.
- `padColor`:
  - 샘플 줄이 없거나 부적합할 경우 `page.paperColor()`(바탕색)를 보장.

### 2) 2쪽 펼침면(Spread) 분할 안전성 보장
- `Gutters.kt`의 `collapseGutters`:
  - 좌우 두 쪽으로 분할하여 처리할 때, 한쪽만 줄어들고 다른 쪽은 줄어들지 않는 경우(`done0 == null || done1 == null`)를 즉시 감지.
  - 한쪽만 줄어들어 좌우 정렬이 파괴되는 것을 막기 위해 **펼침면 전체를 건드리지 않고 원본을 안전하게 유지(`return null`)**하도록 개선.

### 3) 단위 테스트 추가 (`GuttersTest.kt`)
- `검은 바탕 쪽에 스캔 가장자리 흰 줄이 섞여 있어도 위아래 여백을 검은색으로 채운다`: 스캔 테두리 흰 줄 오염 방지 검증.
- `좌우 펼침면에서 한쪽만 줄어들어 양쪽 칸의 높이가 어긋나는 경우 펼침면을 건드리지 않는다`: 펼침면 좌우 불균형 축소 방지 검증.

### 4) 캐시 키 갱신
- `cacheKey`: `"gutters-23"` -> `"gutters-24"`로 증가.
